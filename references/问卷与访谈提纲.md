# 问卷 / 访谈提纲设计

**这不是可选加项**：官方模板附录写明「若论文包含访谈或问卷，须附访谈提纲或问卷设计」。用户的研究方法里有问卷或访谈，附录就得有对应的东西，否则自查 A 组的「附录」和 B 组的「研究方法可操作」两条都过不了。

## 一、什么时候主动问用户

命中下面任一条，就用 AskUserQuestion 问一次「要不要我帮你把问卷/访谈提纲拟出来」：

| 触发条件 | 该给什么 |
|---|---|
| 选题引导第 2 轮答「能发问卷（数百份）」 | 问卷 |
| 选题引导第 2 轮答「能拿一手材料·能访谈」 | 访谈提纲 |
| 论文类型判为**调研分析型** | 问卷（通常还要配少量访谈） |
| 论文类型判为**案例分析型** | 访谈提纲 |
| 研究方法一节写了「问卷调查」「深度访谈」「半结构化访谈」 | 对应那项 |

问的时机：**定题之后、起草研究方法之前**。太早问用户还没定方向；等到正文写完再问，方法一节的样本量、量表维度就得回头改。

问法给三个选项：「问卷 + 访谈提纲都要」/「只要其中一项」/「先不用，我自己写」。用户说不用就不做，也不追问第二遍——但要提醒他附录这一项还空着。

## 二、开题阶段的关键前提：问卷还没发

开题报告是**研究计划**，绝大多数用户此时**尚未实施调查**。所以：

- 正文一律写「**拟**发放问卷 X 份」「**计划**访谈 8–12 人」，**不要写成已经做完了**（"共回收有效问卷 217 份，Cronbach's α 为 0.86"——这是编数据，学术不端）。
- 附录附的是**问卷设计稿 / 访谈提纲**，不是数据结果。
- 信效度只能写**拟如何检验**（预调研 30–50 份、算 α 系数与 KMO），不能给具体数值。
- 若用户说问卷已经发过了、有真实数据，那就按他给的实际数字写，并让他自己核对。**不替用户估算或补全任何一个数**。

## 三、问卷结构（六段，按顺序）

1. **卷首语**：研究目的（一两句，不必写全称课题名）、**匿名与保密承诺**、预计填答时长、致谢。伦理上这段不能省。
2. **甄别题**：确认答卷人属于目标群体（如"您目前是否在社区居委会/社区工作站任职？"），不符合的直接结束。
3. **人口学变量**：性别、年龄段、学历、工作年限、岗位/职级、所在街道。**只问分析真用得上的**——问了不分析就是废题，答卷人也会烦。
4. **主体量表**：核心，见下节。
5. **开放题**：1–2 题，收量表覆盖不到的信息（"您认为当前最需要减掉的是哪一类工作？"）。别多，多了没人填。
6. **结束语**：再次致谢 + 说明数据仅用于学术研究。

## 四、量表怎么设计

- **优先用成熟量表**，别自己造。用了就**必须标注来源出处**（作者、年份、原量表名），改编过要说明改了什么、为什么。
  > 硬规矩：**不要臆造量表来源**。想不起确切出处就写"参考〈某类〉量表编制，来源待核验"，并提示用户在知网核对——同参考文献的规矩一样，见 `references/文献检索.md`。
- **李克特 5 点**（很不同意→很同意）是 MPA 问卷的默认选择；需要更细的区分度再用 7 点。同一份问卷别混用不同点数。
- **每个变量 3–5 个题项**。少于 3 题算不出可靠的信度系数。
- **设 1–2 道反向题**防乱填（如"我认为现有台账数量是合理的"），录入时记得反向计分——这点要在正文方法一节写明。
- **题项数决定样本量**：题项数 × 5~10 倍，且**不少于 200 份**（低于这个数评委会质疑代表性）。25 个题项 → 200~250 份是稳妥区间。

**逐题必查的六条**（写完每题过一遍）：

| 病 | 例（错） | 改法 |
|---|---|---|
| 一题两问 | "您对考核频次和考核内容满意吗？" | 拆成两题 |
| 诱导性 | "您是否也认为台账负担过重？" | "您如何评价当前台账工作量？" |
| 双重否定 | "您不认为不该减少督查吗？" | 正面表述 |
| 专业术语 | "您所在单位的行政发包程度如何？" | 换成答卷人能懂的说法 |
| 选项不互斥 | 年限："1–3年 / 3–5年" | "1–3年 / 4–6年" |
| 选项不穷尽 | 学历漏了"高中及以下" | 补齐或加"其他" |

## 五、访谈提纲怎么设计

- **半结构化**：定主干问题，留追问空间。全结构化的就该做问卷了。
- **8–12 人**为常见区间，关键是**分层**——不能只访居委会书记。基层治理类研究至少覆盖三类：一线工作人员 / 街道条线负责人 / 服务对象（居民）。**样本构成比人数更重要**，正文要说明为什么这样抽。
- **提纲按主题分 3–4 组**，每组 2–4 个开放式主问题 + 每题下挂 1–2 个**追问点**（"能举个具体例子吗？""这种情况多久发生一次？"）。追问点写出来才叫可操作。
- **问题从易到难**：先问工作日常，再问评价与困难，最后问改进建议。开场就问敏感问题会封住话头。
- 一并写明：**预计单次时长**（40–60 分钟）、是否录音、**知情同意与匿名化处理**（受访者以"A1、A2"编号呈现）。这几项是伦理要求，评委会看。

## 六、放进哪里

**正文**（`content_by_section`）里的「研究方法」一节写清楚：对象、抽样方式、拟发放/拟访谈规模、工具（哪套量表、几个维度）、拟如何检验信效度。别只写"采用问卷调查法"——自查 B 组「方法只列名不可操作」就是卡这个。

**问卷与提纲全文放 `appendix`**：

```json
"appendix": [
  "附录A  社区工作者行政负担感知问卷（设计稿）",
  "尊敬的女士/先生：您好！本问卷仅用于学术研究，全程匿名……",
  "第一部分  基本情况",
  {"list": ["您的工作年限：□1年以下 □1–3年 □4–6年 □7年以上",
            "您所在社区常住人口规模：□5千以下 □5千–1万 □1万以上"], "ordered": true},
  {"table": {"caption": "负担感知量表（1=很不同意，5=很同意）",
             "headers": ["题项", "1", "2", "3", "4", "5"],
             "rows": [["我经常需要在多个系统重复填报同类数据。", "", "", "", "", ""],
                      ["上级要求的报表多数与我的服务对象无直接关系。", "", "", "", "", ""]]}},
  "附录B  访谈提纲（半结构化）",
  "一、工作日常（对象：社区一线工作人员，预计40–60分钟）",
  {"list": ["请描述您一天的主要工作内容？（追问：哪几项最占时间？）"], "ordered": true}
]
```

两件必须知道的事：

- **`appendix` 与 `content_by_section` 用同一套混排块**（纯字符串 / `{"table":…}` / `{"list":…}` / `{"image":…}`）。所以**量表题要排成真表格**：表头 `["题项","1","2","3","4","5"]`，每题一行——不要再把「题干 □1 □2 □3 □4 □5」硬挤成一行。附录里的表和图走**独立编号**「附表1 / 附图1」，不占正文那套连续的「表1 / 图1」。
- **附录不计入正文字数**（`build_from_template.py` 只统计 `content_by_section`）。所以拟问卷**不会**帮用户凑篇幅档位的字数，篇幅仍要靠正文写够。

## 七、常见病（评委必问，见 `references/论文类型详解.md`）

- **非本人发放** —— 委托他人代发、或直接用单位现成数据，代表性会被质疑。正文要写明由本人发放。
- **样本不足或无代表性** —— 只发给熟人、只覆盖一个社区。
- **缺信度效度检验** —— 一个字不提 α 系数和 KMO。
- **问卷设计缺陷** —— 量表无来源、维度和研究框架对不上（框架讲三个维度、问卷只测了两个）。
- **问卷和访谈两张皮** —— 各做各的，没有三角互证的说明。
