# 一站式收尾（自查通过后的可选交付物）

用 **AskUserQuestion 多选**问用户还需要哪些交付物，**明确告知"都不需要也可以，直接结束"**。用户选了哪几项就做哪几项，逐项交付并给出文件路径；未选的不做、不追问第二遍。

**生成顺序**：
1. **PPT 先生成**（用户选了的话）——PPT 的页数和结构确定后，演讲稿才能逐页写
2. **演讲稿 + 答辩问答可并行**——演讲稿依赖 PPT 结构，答辩问答基于 content.json 即可；两者互不依赖，可同时生成
3. 若用户没选 PPT，演讲稿和答辩问答均可直接生成，互不阻塞

## 1. 汇报 PPT

先问用哪套内置模板——`模板1` / `模板2` / `模板3`（均为北航答辩通用、16:9，见 `assets/templates/ppt/`），或"不用模板，只要 markdown 大纲"。

**选定模板后先做依赖前置检查**（生成前跑一次，别等报错）：

```bash
python3 -c "import pptx; print('python-pptx', pptx.__version__)"
```

若报 `ModuleNotFoundError`，**用 AskUserQuestion 问用户是否安装**（不要擅自装、也不要静默放弃），选项给三个：

- 「安装（推荐）」→ 征得同意后执行 `pip install python-pptx`（或 `python3 -m pip install python-pptx`），装完复跑检查再生成；
- 「不安装，改为 markdown 大纲」→ 直接产出逐页 PPT 大纲（每页标题 + 要点），用户自己粘进 PPT；
- 「跳过 PPT」→ 不做这项，继续收尾其他选项。

检查通过后，**优先从 content.json 自动派生 ppt_content.json**（省去手工重复写），只需微调即可：

```bash
python "$SKILL/scripts/derive_ppt_content.py" \
  --content content.json \
  --output ppt_content.json
```

派生后**务必按下面的密度要求检查并补充**——自动派生的 bullets 可能偏长或偏少，需要人工微调。若自动派生效果不好（如章节映射不对），再手工写。

若没有 content.json（用户只要 PPT 不要 docx），则手工写 ppt_content.json（`title` / `cover{作者姓名,指导教师,日期}` / `chapters[{name, slides[{title, bullets}]}]`），**内容必须满足以下密度要求**：

### PPT 内容生成规范（写 ppt_content.json 前必读）

**总页数目标**：8 分钟汇报 → **12–15 页**（含封面、目录、致谢）；10 分钟 → 15–18 页；15 分钟 → 18–22 页。**宁可每页说透，不要拆太多页导致每页太空。**

**每页规范**：
- 标题：一句话概括本页核心观点（不是"研究背景"这种泛标题，而是"开源软件已成关基系统核心组件"）
- 要点：**3–5 条**，每条 ≤25 字；有数据的优先放数据（"91%""76%"比"很多"有力）。**模板文本框有固定尺寸，bullets 太长会溢出**——宁可精炼也不堆字
- **关键页嵌入图表**：研究框架页、技术路线页、实施计划页——在 bullets 里写 `【图：xxx】` 或 `【表：xxx】`，提醒用户插入
- 一页能说清楚的事不要拆两页；只有当内容确实放不下时才拆页
- 如果 bullets >5 条且无法精简，才考虑拆成两页

**各章参考分配（8 分钟 / 12–15 页）**：

| 章节 | 页数 | 内容要点 |
|---|---|---|
| 研究背景与问题 | 1–2 页 | 宏观背景+具体问题/案例+数据，一页说透；问题多可拆两页 |
| 选题意义 | 1 页 | 理论+现实意义合并，4-6 条讲透 |
| 文献综述与研究空白 | 1–2 页 | 各线索现状+空白+本文定位，一页能放下就一页 |
| 研究框架 | 1–2 页 | 框架总览（含图）+各层说明，重要章节可给 2 页 |
| 研究思路与技术路线 | 1–2 页 | 思路+路线图（必须嵌入路线图.png） |
| 研究方法 | 1 页 | 三种方法+各自细节，4-6 条讲透 |
| 创新之处 | 1 页 | 逐点展开，4-6 条 |
| 实施计划 | 1 页 | 时间表（甘特图或表格），一页够 |

**绝对不能出现**：
- 章节名直接当页面标题（如标题写"文献综述"而不是该页的具体观点）
- bullets 里写"详见论文第 X 章"（PPT 是独立汇报，不是论文目录）
- 占位文字残留（"添加技术路线图""见下页"等——要么嵌入实际内容，要么写 `【图：xxx】` 占位）
- 每页只有 2-3 条 bullets 的"空洞页"（要么补充内容，要么合并到相邻页）

### PPT 设计规范（提升视觉质量）

#### 一、叙事弧线（Nancy Duarte 原则）

PPT 不是信息陈列，是**故事**。评审听了一天答辩，你需要让他们"跟着走"，不是"自己读"。

**每页只承载一个核心观点**，整个 PPT 的叙事结构：

| 阶段 | 页数 | 内容 | 情绪 |
|------|------|------|------|
| **痛点开场** | 1 页 | 一个具体场景/数据/案例，说明"问题很严重" | 紧张 |
| **冲突** | 1-2 页 | 现有研究的不足 / 争议 / 矛盾 | 好奇 |
| **我的方案** | 3-5 页 | 研究框架 + 方法 + 创新点 | 希望 |
| **承诺兑现** | 1-2 页 | 预期成果 + 实施计划 | 信任 |

**具体写法**：
- 研究背景页**不要**从"随着...的发展"开头，**要**从一个具体事件/数据开头（"2024年某市政务系统因开源组件漏洞导致数据泄露"）
- 文献综述页**不要**罗列"张三说...李四说..."，**要**展示冲突（"现有研究认为 A，但 B 认为矛盾，本文要解决这个矛盾"）
- 创新点**不要**藏在最后，**要**在开头就预告（"本研究的新在于..."），后面每页都在兑现

#### 二、视觉优先（Garr Reynolds 原则）

> "能用图就不用文字，能用数字就不用句子。"

**每页的视觉焦点**（选一个，不要都放）：

| 类型 | 适用场景 | 示例 |
|------|---------|------|
| **大数字** | 数据页 | 页面中间放 **91%**，下面小字"企业开源组件使用率" |
| **流程图** | 研究框架、技术路线 | 框+箭头，不要用文字描述流程 |
| **表格** | 方法对比、实施计划 | 三行表格比五段文字清楚 |
| **图片** | 案例、场景 | 一张截图胜过一百字描述 |

**bullets 减法**：
- 当前：3-5 条 × 25 字 → 目标：**1-2 条 × 10 字**（关键词，不是句子）
- 能砍就砍：如果一条 bullet 超过 15 个字，拆成"关键词 + 口头解释"
- PPT 是**提示卡**，不是讲稿——详细内容你口头说

#### 三、排版与留白（Guy Kawasaki 原则）

**字号**：
| 元素 | 建议字号 | 说明 |
|------|---------|------|
| 页面标题 | 44pt 加粗 | 一句话概括本页观点 |
| 正文关键词 | 18-20pt | 每页 1-2 个关键词 |
| 图注/来源 | 10-12pt 灰色 | 不抢主体视线 |

**留白**：
- 每页内容只占**60% 面积**，40% 留白
- 页边距至少 0.5 英寸
- 内容块之间 0.3-0.5 英寸呼吸空间
- **宁可少放内容，也不要塞满**

**配色**：
- 北航蓝（#003366 / #005BAC）为主色
- 60-30-10 法则：60% 白底、30% 主色、10% 强调色（数据/重点）
- 数据图表用对比色突出重点

**布局变化**（不要每页一样）：
- 左图右文（研究框架页）
- 大数字+小标签（数据页）
- 表格（方法对比页）
- 流程图/时间线（实施计划页）

#### 四、避坑清单

**绝对不能出现**：
- 章节名直接当页面标题（"文献综述"→ 应写具体观点）
- bullets 里写"详见论文第 X 章"
- 占位文字残留（"添加技术路线图""见下页"）
- 每页只有 2-3 条 bullets 的"空洞页"
- 标题下划线 / 彩色横条装饰（AI 生成典型特征）
- 浅色背景配浅色文字（对比度不够）
- 居中正文段落（只居中标题）

```bash
python "$SKILL/scripts/build_ppt_from_template.py" \
  --template "$SKILL/assets/templates/ppt/模板1-北航答辩通用.pptx" \
  --content ppt_content.json \
  --output "开题汇报-<题目>.pptx"
```

脚本"改而不建"：只挑模板里需要的页、替换占位文字、复制内容页给各章、删除未用页并按 封面→目录→各章(章节页+内容页)→致谢 重排；自动清除模板作者水印与装饰样例文字（"JUNE 12th""XX""小标题一"等）。生成后打印自检（页数/题目/章节数/水印/残留占位），把自检结果一并回显给用户。**只用 skill 内置副本，勿改工作目录里的原模板。**

> 依赖 `python-pptx`。上面的前置检查是为了**先问用户、而不是先报错**；若仍撞上，脚本会打印安装命令与降级建议并以退出码 1 干净退出（不生成半成品文件）。任何情况下都**不要因为缺依赖卡住整个流程**——问清用户意愿后走安装或降级。

## 2. 汇报演讲稿

生成前用 **AskUserQuestion** 问时长与形式（两问可合并为一批）：
- 时长：8 分钟（推荐）/ 10 分钟 / 15 分钟 / 自定义
- 形式：逐字稿（完整口播稿）/ 提纲式提示卡（要点+提示）按篇幅折算字数（口播约 200–240 字/分钟），逐页对应 PPT，同样按 `references/去AI化写作守则.md` 写成口语可讲的稿子（此处允许比正文口语化）。

**交付格式：默认 Word（.docx），非 markdown。** 用 python-docx 生成结构化 Word：大节用 Heading 1、小节用 Heading 2、正文用正文段样式，标题/正文字体用宋体（中文）、标题加粗，方便用户直接打印或编辑提交。只有当用户明确说"只要 md / 文本"才降级为 `.md`。产出后用 `python3 -c "import docx"` 检查依赖，缺失则提示 `pip install python-docx`（参考下文降级，不擅自装）。

## 3. 答辩问答预测

按"评审标准 + 优秀标准 + 本文薄弱处"预测 10–15 个高频问题（选题价值、概念界定、理论适配、方法可行性、样本代表性、数据可得性、创新点成立性、对策可操作性等），每题给要点式答法；对确实是弱点的，**如实提示补强方向而不硬辩**。

**交付格式：默认 Word（.docx），非 markdown。** 每题用编号问题作小标题（Heading 2）、答法作正文；问题的"薄弱点"属性可加标注或使其条目级样式突出，便于临场查阅。只有用户明确说"要 md / 文本"才降级为 `.md`。与演讲稿共用 python-docx 生成与依赖检查方式。

## 4. 多份格式导出

按需再产出 markdown 全文 / 纯文本 / 提纲摘要，便于贴到邮件或系统表单。
