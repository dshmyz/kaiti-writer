# 审阅 / 修订已有稿

适用：用户已经有一份开题报告（自己写的、导师退回的、或上一轮生成的），要评一遍或改一遍——**不是从零起草**。

## 流程

### 1. 拿到文件

问用户文件路径（**必须由用户提供，不要自己去猜路径或翻目录**）。用户也可以直接把正文粘进对话，那就跳过第 2 步。

支持 `.docx`。若是老 `.doc`（OLE 格式，打不开）：

```bash
textutil -convert docx 我的开题报告.doc
```

### 2. 读进来

```bash
python "$SKILL/scripts/read_docx.py" --input "用户给的路径.docx"
```

只读，不动原文件。脚本会跳过封面与目录（用正文「开题报告」标题作起点），按节切分并报出每节段数与字数，末尾提示缺失的常规节、「预期目标和成果」，以及**正文提了问卷/访谈但附录为空**（模板硬要求，补法见 `references/问卷与访谈提纲.md`）。

要拿结构化数据供改写用，加 `--json out.json`；要看全文加 `--full`。

**若脚本识别到的节数明显偏少**（比如用户的标题写法是「1.1 研究背景」而非「（一）研究背景」），别硬套——直接读文件或让用户确认章节划分。

### 3. 逐条核

对着 `references/自查清单.md` 全条核对，重点看这几处最容易出问题的：

| 常见问题 | 判断依据 |
|---|---|
| 文献综述是罗列而非分类梳理 | 有没有主题分类、有没有指出研究空白 |
| 文献不够或过旧 | ≥15 篇、近 5 年过半（见 `references/文献检索.md`） |
| 研究方法只列名不可操作 | 有没有对象、工具、步骤、信效度 |
| 创新之处空泛 | 是否落到六方面之一，而非「首次研究」 |
| 缺「预期目标和成果」 | 官方模板无此节，多数人会漏；落点见下 |
| 无技术路线图 | 「（一）研究思路」只有文字 |
| 表无表题 / 图无图题 | 格式规范：表题在表上、图题在图下 |
| 有 AI 味 | 按 `references/去AI化写作守则.md` 的特征词与句式判断 |

引用了文献的，**不要替用户核实卷期页码**——拿不准就标「待核验」并让用户在校园网/知网核。

### 4. 输出结果给用户看

按 `references/自查清单.md` 末尾的回显格式，markdown 呈现、逐条 ✅/⚠️、结尾一行结论。**⚠️ 项要写清「哪一句/哪一段」有问题、具体怎么改**，不要只说「建议加强」。

### 5. 问是否要据此重建

用 AskUserQuestion 问用户要不要按修改意见出新稿，选项：

- **改哪几节** → 只重写有问题的节，其余保留用户原文
- **全文重写** → 保留题目与研究方向，正文按标准流程重来
- **只要意见，我自己改** → 到此结束

要出新稿就走 SKILL.md 第 5 步：把「原文保留的 + 改写过的」一起写进 `content.json`，用 `build_from_template.py` 生成。改写时按 `references/去AI化写作守则.md` 落笔，别把 AI 味改进去。

## 导师反馈循环

适用：用户拿到导师退回的稿子，带着导师的修改意见（批注、截图、语音转文字、甚至口头转述）要改——**不只是审阅，是要执行修改**。

### 1. 收集意见

把导师给的所有反馈**一次性收齐**：docx 批注、截图、语音转文字、聊天记录截图、口头复述的文字版。不要分批——先列一轮完整清单再动手，避免改到一半发现还有意见没收到。

### 2. 解析成结构化清单

把散乱意见**按节分组**，转成可执行的 checklist：

```
导师意见清单（共 N 条）：

【文献综述】 3 条
- [ ] "文献太旧了" → 近 5 年文献占比不足 → 按文献检索.md 补 5-8 篇 2020 年后的
- [ ] "没有分类" → 用主题分类法重写综述结构
- [ ] "缺少 XX 领域的文献" → 补充公共价值/数字治理方向文献

【研究方法】 2 条
- [ ] "问卷没说信效度" → 加 Cronbach's α 和 KMO 检验说明
- [ ] "样本量不够" → 补充抽样依据和目标样本量计算

【创新之处】 1 条
- [ ] "创新不明显" → 收窄到"视角创新"，删掉其余三条
```

**规则**：
- 每条意见必须映射到一个**具体操作**（补什么、改什么、删什么），不能留"加强""完善"这种模糊指令
- 导师说的"加强"翻译成具体动作：加强文献→补 5+ 篇近 5 年的；加强方法→补工具、步骤、信效度
- 同一条意见跨多节的（如"逻辑不清楚"），拆成每节各自的改法
- 有矛盾的两条意见（如"精简"vs"展开"），列出来让用户决定取舍，不要自作主张
- 清单列完后**给用户确认**，选项「就这样改 / 有遗漏要补 / 需要调整优先级」

### 3. 逐条执行

按清单逐条改。每改完一条，在清单里标 ✅。改的过程中：

- **保留用户原文的风格和用词**——只改导师指出的问题，不要顺手"优化"别的段落
- 改完一节后**只问导师意见涉及的那几处**，不要整节重新确认
- 改动涉及跨节联动（如删了一个理论框架导致文献综述也要删对应段），把联动改动也标在清单里

### 4. 改完跑自查

全部改完后，跑一遍 `references/自查清单.md` 的完整自查（参照上面"逐条核"步骤），**重点看改动是否引入了新问题**（删了某段后上下文断裂、补了文献但引用格式不统一等）。

输出格式：先显示导师意见清单的完成状态（每条 ✅），再附自查结果。用 AskUserQuestion 问「导师意见都改完了，自查也过了——要我出新 docx 吗？」

### 5. 出稿

走 `build_from_template.py` 出 docx。若改动量大（改了 3 节以上），建议用户把新稿和导师意见清单一起发给导师，方便逐条对照确认。

## 两处容易踩的坑

**「预期目标和成果」** 官方模板正文只有一~四章，没有这一节，但《管理办法》第三条要求。`build_from_template.py` 会在 `content_by_section` 里给出 `"五、预期目标和成果"` 时自动建节（插在参考文献前，标题样式与其他章一致）。审已有稿时若发现缺，就提示用户补这一节。

**技术路线图** 「（一）研究思路」要求「文字 + 技术路线图」。已有稿常只有文字。可以直接生成：

```bash
python "$SKILL/scripts/make_route_figure.py" --content route.json --output 路线图.png
```

`route.json` 里 `nodes` 数组元素为字符串=单框、为数组=并列分支；出图后用 `{"image": "路线图.png", "caption": "本研究技术路线图"}` 块嵌入。用户自己有图就直接用他的路径。
