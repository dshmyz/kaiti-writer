# 参考文献著录规范（GB/T 7714）

## 正文标注
- 格式 `[序号]`，上角标，小四号 Times New Roman，置于方括号中，放在引文/转述观点最后一个句号之前，如"…成果[1]"。
- 多篇同引 `[1, 2, …]`，方括号内序号按增序排列。
- 直接说明时序号与正文排齐，如"由文献[8, 10-14]可知"。
- 序号规则二选一全文统一：按正文首次引用先后递增，或按第一作者姓的字母顺序递增；同一论著多处引用以首次出现的序号为准。

## 著录通则
- 序号左顶格 `[1]`，每条末不加结束符。
- 标点用"半角标点 + 空格"。
- 作者≤3 位全列；>3 位列前 3 位加"，等"或"，et al"。
- 中外作者一律姓前名后；外文名用首字母大写代（William E. Johns → Johns W.E.）。
- 页码不可省，起止用 `-`，不同范围用 `,`。
- 缺项可将该项连同对应标点一并略去。

## 文献类型标识
| 类型 | 代码 | 类型 | 代码 |
|---|---|---|---|
| 期刊 Journal | J | 标准 Standard | S |
| 专著 Monograph | M | 报纸文章 Newspaper | N |
| 论文集（单篇） | A/C | 报告 Report | R |
| 学位论文 Dissertation | D | 资料汇编 General | G |
| 专利 Patent | P | 其它 | Z |

电子文献类型：数据库 DB、计算机程序 CP、图书 M、电子公告 EB。
载体标识：磁带 MT、磁盘 DK、光盘 CD、联机网络 OL。
电子文献写法：`[类型/载体]`，如 `[DB/OL]` 联机网上数据库、`[EB/OL]` 网上电子公告、`[J/OL]` 网上期刊、`[M/CD]` 光盘图书。

## 各类条目示例

**期刊（8 项）**：`[序号] 作者. 文献题名[J]. 刊名, 出版年份, 卷号(期号): 起止-页码`
```
[1] 毛峡, 丁玉宽. 图像的情感特征分析及其和谐感评价[J]. 电子学报, 2001, 29(12A): 1923-1927
[2] Ozgokmen T M, Johns W E, Peters H, et al. Turbulent Mixing in the Red Sea Outflow Plume[J]. Journal of Physical Oceanography, 2003, 33(8): 1846-1869
```

**专著（≥7 项）**：`[序号] 作者. 书名[M]. 版次(首次免注). 译者. 出版地: 出版社, 出版年: 起止-页码`
```
[3] 刘国钧, 王连成. 图书馆史研究[M]. 北京: 高等教育出版社, 1979: 15-50
```

**论文集（9 项）**：`[序号] 作者. 题名[A]. 主编. 论文集名[C]. 出版地: 出版社, 出版年: 起止-页码`
```
[4] 毛峡. 绘画的音乐表现[A]. 中国人工智能学会2001年全国学术年会论文集[C]. 北京: 北京邮电大学出版社, 2001: 739-740
```

**学位论文（6 项）**：`[序号] 作者. 题名[D]. 保存地: 保存单位, 年份`
```
[6] 张和生. 地质力学系统理论[D]. 太原: 太原理工大学, 1998
```

**专利（8 项）**：`[序号] 专利所有者. 专利题名[P]. 作者排名. 专利国别: 专利类型, 专利号, 发布日期`
```
[7] 姜锡洲. 一种温热外敷药制备方案[P]. 中国专利: 881056078, 1983-08-12
```

**标准（6 项）**：`[序号] 标准代号, 标准名称[S]. 出版地: 出版者, 出版年`
```
[9] GB/T 16159—1996, 汉语拼音正词法基本规则[S]. 北京: 中国标准出版社, 1996
```

**报纸（6 项）**：`[序号] 作者. 题名[N]. 报纸名, 出版日期(版次)`
```
[10] 毛峡. 情感工学破解"舒服"之迷[N]. 光明日报, 2000-4-17(B1)
```

**报告（6 项）**：`[序号] 作者. 文献题名[R]. 报告地: 报告会主办单位, 年份`
```
[7] 冯西桥. 核反应堆压力容器的LBB分析[R]. 北京: 清华大学核能技术设计研究院, 1997
```

**电子文献（6 项）**：`[序号] 作者. 电子文献题名[类型/载体]. 网址或出处, 发表或更新日期/引用日期(任选)`

## 写入前收尾核查（生成 refs / 写进 docx 前必做）

生成参考文献表（写进 `content.json` 的 `refs`、再转成 docx）前后，**每一项都必须通过下面核查**。这一步不是可选的自查，是"能交出去"的底线——曾有开题报告的 16 条文献全因末尾带句号被导师/格式文档打回，根因就是漏掉这里的检查。

逐条核对，任一不满足就当场改：
1. **条目末尾不得有结束符**：删掉每项最后残留的句点 `.`（以及顿号、逗号、分号等多余标点）。GB/T 7714 与北航格式文档均要求"每条最后不用加结束符"。正则：`re.sub(r'[.,;:、，。；：]+$','',条目)`。
2. **不得出现"待核验/待补/〈XXX〉/TODO"占位**：占位必须清空。**若该项确缺真实数据（发文字号、出版社、卷期页等），按"缺项连同对应标点一并略去"处理**——删掉占位及其紧邻标点，如 `[Z]. （发文字号待核验）` 清成 `[Z]`，而不是留着括号。缺项信息另行单独列给用户核验，不要写进条目里。正则（删成对括号内含待补字样者）：`re.sub(r'[（(][^（）()]*?(?:待核验|待补|待验证|TODO)[^（）()]*?[）)]','',条目)`。
3. **标点统一为"半角 + 空格"**：参考文献条目不出现全角括号 `（）`（应作 `()`）、全角逗号顿号等；英文文献尤其注意 `Vulnerabilities(SP 800-218)` 与括号间留一个半角空格。
4. **作者数**：≤3 位全列；>3 位列前 3 位 + `, 等`（中文）或 `, et al`（英文）；中外一律姓前名后、外文名用首字母大写缩写。
5. **页码**：不可省略，起止用 `-`。
6. **docx 与 content.json 同步**：修了哪一份，另一份对应项必须同改，否则下次重生成会覆盖回来。改完比对 `content.json["refs"]` 与 docx 实际段落一致。
7. **序号连续性**：`[1][2][3]…` 无跳号、无重复；与"每项末不加结束符"一起再过一眼。

把这些规则固化成一段脚本（如 `scripts/fix_refs.py`），生成 refs 后直接跑一遍再写进 json/docx；让"收尾核查"成为流程步骤而非凭印象。

## 缺项的就地标注：工作稿 vs 定稿（分两层，别搞混）

命中第 2 条"缺真实数据"的条目，除了从正文清掉占位，还要让**用户**知道该补哪。做法分两层，两层状态刻意不一样：

- **content.json（源）永远干净合规**：缺项一律按第 2 条"连标点一并略去"清成无占位居文本（如 `[Z]`）。源里**不放**任何"待补"字样。这样源随时可重生成一份合格正式稿。
- **docx（工作稿）可带红色待补提示**：当正处在"待核验、还没补真值"阶段，需提醒用户补哪些字段时，在 docx 里**就地追加一个红色（FF0000） run**，写明 `〈发文字号待补〉` / `〈作者与卷期页待核验〉` / `〈出版社与年份待核验〉` 等。用户补完 → 删掉这只红色 run → 文档恢复 GB/T 7714 完全合规，即可定稿。

要点：
- 红色提示 run 复制本条首个 run 的 `rPr`，只在其上叠加 `<w:color w:val="FF0000"/>`，保证字体/字号与正文一致，仅颜色不同；文本前加一个空格分隔，`<w:t xml:space="preserve">`。
- **不编造真值**：红色提示只是提醒"这里有缺项要补真实数据"，不是替用户填。补的数据必须由用户核验后提供（真实可查证）。
- 定稿检查：把 docx 里所有 `val="FF0000"` 的 run 清掉，再对照第 6 条与源一致性复核即可交付。
