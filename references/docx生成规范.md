# docx 生成规范（build_from_template.py 详解）

本文件从 SKILL.md 抽出，记录开题报告 .docx 的完整生成细节。SKILL.md 中只保留一句话引用。

## 命令

```bash
python "$SKILL/scripts/build_from_template.py" \
  --template "$SKILL/assets/templates/开题报告模板.docx" \
  --content content.json \
  --output "开题报告-<题目>.docx"
```

**改稿时加 `--diff` 参数**：传入旧版 docx 路径，生成后自动输出"新增/删除/修改了什么"的逐段 diff 清单：

```bash
python "$SKILL/scripts/build_from_template.py" \
  --template "$SKILL/assets/templates/开题报告模板.docx" \
  --content content.json \
  --output "开题报告-<题目>.docx" \
  --diff "开题报告-<题目>-旧版.docx"
```

## content.json 格式

`content.json` 格式见 `templates/内容示例-社区减负.json`：

- `title`/`subtitle`：题目主/副标题；`subtitle` 为空则自动删副标题空行。
- `cover`：`{"作者姓名":"...","专业名称":"...","指导教师":"...","培养学院":"..."}`，四项均可选；未给则保留模板默认（公共管理/公共管理学院）。
- `content_by_section`：键为模板里已有的节标题文本（如`"（一）研究背景"`、`"研究框架（内容）"`、`"四、学位论文实施计划"`），值为该节内容数组，**按数组顺序依次插入**。数组元素可以是纯文本段落（字符串），也可以是下面四种**混排块**（对象），可自由穿插：

| 块 | 写法 | 生成结果 |
|---|---|---|
| 表格 | `{"table":{"headers":[...],"rows":[[...]],"caption":"访谈对象分布"}}` | 学术三线表 + **表题在表上方**（五号宋体加粗居中，自动编号"表1/表2…"） |
| 插图 | `{"image":"/abs/path/技术路线图.png","caption":"技术路线图","max_width_cm":14}` | 嵌入图片（按原始像素等比缩放，默认最宽 14cm 不超版心）+ **图题在图下方**（自动编号"图1/图2…"） |
| 列表 | `{"list":["第一点","第二点"],"ordered":true}` | Word 真实自动编号列表；`ordered:true`→`1. 2. 3.`，省略或 false→`●` 项目符号 |
| 脚注 | `{"text":"这是正文段落。","footnote":"注文内容，如资料来源说明。"}` | 该段落末尾加上标注号 + 页脚注文 |

图/表题**编号全局连续**（跨节累加），符合 `references/格式规范.md`「表题在表上、图题在图下」。图片路径须为**已存在的本地绝对路径**，不存在则打印警告并跳过该块（不中断生成）。四类论文的 content.json 示例见 `templates/内容示例-*.json`（`-社区减负`=问题研究型且**演示四种混排块**、`-案例分析`、`-调研分析`、`-政策分析`）。**勿改键名**否则找不到节。

> 示例文件带 `"_demo": true`：它们的封面、参考文献故意留 `〈XXX〉` 占位（换成像真的假文献会诱导用户直接交编造的引文），这个键让自检把占位警告标注成"示例预期如此"。**给用户建 content.json 时不要带这个键**，否则真占位也会被标成预期。

> **`"五、预期目标和成果"` 是例外**：官方模板正文只有一~四章，没有这一节（模板里"预期"出现 0 次），但《管理办法》第三条把它列为 7 项必备之一。给这个键，脚本会**自动建节**——插在「参考文献：」之前，标题样式克隆「三、」（`pStyle=3` 故 F9 后自动进目录、四号字合规），重复运行不会建出第二个。模板原文写有「可按照导师建议进行调整」，故新增章节符合模板意图。**这是白名单里唯一可自动新建的节**，其他键名拼错仍会报「⚠️ 未找到节标题」。

- `plan_table`（可选，兼容旧写法）：实施计划三线表，`{"headers":[...],"rows":[[...]],"caption":"..."}`；给了则在"四、"节末尾生成三线表。新写法建议直接在 `content_by_section["四、学位论文实施计划"]` 里用 `table` 块。
- `refs`：参考文献条目数组（GB/T 7714，见 `references/参考文献著录.md`）。**写进 json 前先跑 `scripts/fix_refs.py` 做收尾核查**。
- `appendix`：附录条目数组，**接受与 `content_by_section` 完全相同的四类混排块**（字符串/表格/插图/列表），附录内的表/图另走一套「附表1 / 附图1」编号。

## 脚本行为

脚本做法：深拷贝模板段落 pPr、只换 run 文本（**不重建文档、保留全部样式**）；替换封面题目与封面表格填写位；在各节标题后插入正文段（宋体/TNR/小四、保留缩进行距）；替换参考文献条目；填附录；**删除末尾"书写规范"段及著录表**；保留模板图片（校徽）。用 **lxml**（非 stdlib ElementTree）解析序列化，原生保留 17+ 个命名空间前缀，避免 Word 提示"需修复"。

脚本在正文区（精确匹配"开题报告"标题之后）查找节标题，不会误插到目录 TOC。生成后**Word 打开时会自动更新目录页码**（脚本置了 `updateFields`，弹"是否更新域"选是即可）。**「五、预期目标和成果」「参考文献」「附录」标题已自动设章级大纲级别（`outlineLvl`=0），F9 刷新后必进目录**。

自检会打印**各节中文字数**，据此对照 `references/篇幅档位.md` 看哪节欠字再补；还会查**未填占位**（`〈〉`/`TODO`/`待补`/`XXX`，正文、参考文献、封面分开报）；**自查会打印「行距: 通过/⚠️」**。生成时会**自动把目录区/正文区/文末的连续空段折叠为 1 个**（**封面区整体不动**）。

> **文档属性自动去个人信息**：生成 docx/pptx 时会清掉模板 `docProps` 里的作者姓名、邮箱、单位、最后修改人、上次打印时间与批注作者，并把作者写成 `cover.作者姓名`。

> 若用户提供了**新的 .docx 模板**（如学院自定版），用 `--template` 指向它即可，脚本按文本定位通用。

## Python 编码护栏

> **写 Python 处理中文 json / 文本时的编码护栏**：`ensure_ascii=False` 是 **`json.dump()`** 的参数，不是 `open()` 的——写到文件用 `open(path,'w',encoding='utf-8')`，要保留中文可读则 `json.dump(obj, f, ensure_ascii=False)`；**绝不要写成 `open(..., 'w', ensure_ascii=False)`**（会直接抛 `TypeError`）。凡把中文内容落盘，一律显式 `encoding='utf-8'`。

## 参考文献收尾核查

**写进 json 前先跑 `scripts/fix_refs.py` 做收尾核查**（自动去末尾结束符、清"待核验/占位"括号、统一半角标点），核查出"待补/待核验"的真实数据缺项时不要自己编，删占位连标点略去后**单独列清单让用户补真值**。**待核验阶段可顺手在 docx 里就地用 `--mark-missing "6:发文字号待补;11:…"` 给参考文献缺项条目加红色提示**（content.json 保持干净），用户补完用 `--unmark-red` 清除即定稿。**正文里的"噪声红"**用 `--clear-noise-red` 清掉。

**参考文献表除查占位外，还须按 `references/参考文献著录.md`「写入前收尾核查」对每条目过一遍（末尾结束符/全角标点/作者数/页码/序号连续）**——这条是防"16 条全带句号被打回"这类事故的闸门，务必执行。

## 生成后规范检查（build 完成后自动执行）

build 完成后，用 python-docx 读取生成的 .docx，逐条核对以下项目：

### 1. 大纲层级（outlineLvl）

- 每个 Heading 段落检查 outlineLvl 是否正确：
  - 章标题（一、二、三…）→ outlineLvl=0
  - 节标题（（一）（二）…）→ outlineLvl=1
  - 条标题（1. 2. 3.…）→ outlineLvl=2
- 若层级错误，用 make_heading_para 逻辑修正后重新写入

### 2. 盘古空格

- **只处理半角空格（" "），不用 `\s`**——`\s` 会吞目录页码的制表符（曾误伤 8 处）
- 遍历所有段落文本，用正则检测中英文/数字间是否有多余空格：
  - 中文后接英文/数字/左括号 → 删空格
  - 英文/数字/右括号/百分号后接中文 → 删空格
- **跳过规则**（这些空格是格式要求，不能动）：
  - 标题段：Heading 样式、outlineLvl 非 None、`第X章/一、/附录/附件` 开头
  - 图表题注：`图/表 + 数字` 开头（"图1␣␣XXX"编号与题间空半角 2 格是规范要求）
  - 参考文献条目：`[数字]` 开头（GB/T 7714 标点后空格是著录格式）
- 修正方式：直接删除匹配到的空格，写回段落

### 3. 附录标题颜色

- 找到「附录」标题段落，检查 run.font.color.rgb：
  - 若为 FF0000（红色）→ 删除颜色属性
- 检查方式：遍历 paragraph.runs，找到 rPr 里的 w:color 并移除

### 4. 参考文献表

- 读取「参考文献」章节下的所有段落，逐条检查：
  - 每条以 [序号] 开头，序号连续（1, 2, 3…）
  - **末尾不应有结束符**（GB/T 7714：每条最后不用加结束符，与 fix_refs.py 口径一致）
  - 作者名后用 .（英文）或 ．（中文），3人以上用"等"或"et al"
  - 标点用半角（, . : ），中文文献用全角（，。：）
  - 期刊名、卷号、页码格式正确

### 4.5 引用编号按首次出现顺序

- GB/T 7714 顺序编码制：正文标注 [n] 必须按首次出现顺序递增（[8] 不得早于 [2] 出现）
- 扫正文（参考文献表之前）所有 [n] 标注，提取首次出现顺序；有乱序即报
- 违规时提示运行 `scripts/renumber_refs.py --fix` 自动重排（正文标注、文献表序号、content.json 三处同步）
- 正文无引用标注时跳过此项

### 5. 字体与字号

- 章标题：黑体居中（14pt，模板实际字号）
- 节标题：四号黑体居左（14pt）
- 条标题：小四号黑体居左（12pt）
- 正文：小四号宋体（12pt）
- 页码：五号宋体（10.5pt）
- 数字和字母：Times New Roman
- 图题/表题：五号宋体加粗（10.5pt），数字字母五号 Times New Roman 加粗

### 6. 页面设置

- 页边距：上下左右各 25mm（以格式规范.md为准）
- 纸张：A4（21cm × 29.7cm）
- 页码居中，从正文第一页开始

### 输出格式

检查结果打印到控制台，格式：

```
✅ outlineLvl 全部正确
⚠️ 发现 3 处盘古空格，已自动修正
✅ 附录标题颜色正常
⚠️ 参考文献第 5 条末尾不应有结束符，已自动去掉
✅ 字体字号符合要求
✅ 页面设置符合要求
```

若有自动修正，修正后重新保存 .docx。若发现无法自动修正的问题（如参考文献缺项），列出清单提示用户。

## 构建流水线附加步骤

- **Step 4 参考文献质量闸**：构建流程自动跑 `scripts/check_refs_quality.py --content content.json`（类型分布/同行评议占比/近5年/中英构成/待核验残留；带 `--core-journals` 可加核心期刊命中统计）。⚠️ 项是补文献的依据，示例文件带占位文献时报错属预期。
- **`--regress "旧版.docx"` 改稿回归门禁**：构建后自动输出新旧正文逐段差异报告（跳过目录行 tab+页码）。凡与本次修改无关的差异段落即为回归，需排查——防"改 A 伤 B"与句子静默丢失（曾靠手工 diff 才抓到丢句）。
