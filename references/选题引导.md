# 选题引导（用户"没想好题目"时走这条）

适用：用户说"不知道 / 没想好 / 帮我想一个"。目标是用**尽量少的轮次**收敛出一个**能写成**的题目——不是想出一个漂亮题目。

> **MPA 选题死在"数据拿不到"的远多于死在"没创意"。** 所以提问的重心是可行性，不是新颖性；候选卡里最要紧的两栏是「需要什么数据」和「风险」。

---

## 一、提问脚本（三轮问完，别临场决定问什么）

每轮用一次 AskUserQuestion，一次问 2–3 个问题。**照这个脚本走，不要自己重新设计问法**——问法不定就会出现"这轮问了、下轮又问一遍"，也容易把参数拼错。

> **调 AskUserQuestion 的两个硬性要求**（踩过的坑）：
> - `questions` 必须是**真数组**，不是数组的字符串写法。传字符串会直接报 `InputValidationError: The parameter questions type is expected as array but provided as string`。
> - 每个 question 的 `options` 是 2–4 个对象，每个对象要有 `label` 和 `description`；**不要自己加"其他"选项**，系统会自动提供 Other。
> - **每个问题的 `options` 必须有 ≥2 个真实选项，否则别问。** 若某个待确认事项其实只有 1 条既定路径（如论文类型已由决策树判定、没有第二种选择），**不要**用 AskUserQuestion 去问——`options` 少于 2 会让工具直接报 `InputValidationError` 并**连同整批问题一起全部发不出去**（不是只跳过那一条）。此时该"问题"根本不构成决策，把它当作既定前提直接陈述出来继续推进即可；同一批里其他确实有 2 个以上选项的问题才单独保留。
>
> **提交前的硬闸——不管这一轮里有多少个问题，逐个数一遍 options：**
> - 任一问题的 `options` 只有 1 个 → **这个"问题"其实不是决策**。把它**从批次里抽出去**，改成一句既定前提陈述，放进文字里直接推进；**绝不带着它提交**，否则 `options<2` 会让**整批**发不出去。
> - 我**宁可把这一轮拆成两批**（每批只留真问题），也不让任何单选项问题混进多问题批次——拆批没副作用，整批报销才有。
> - 提交给我看之前，"单选项问题"与"≥2 选项问题"逐条核过一遍（列出每个问题的选项数）再动手。
>
> **没有这个工具的智能体**（Codex / Trae / WorkBuddy 等）：直接在回复里把本轮问题写成编号选项、注明"也可自己输入"，然后**停下等用户回答**。三轮脚本的内容与顺序不变，变的只是提问方式。

### 第 1 轮：定学术方向 + 判断有没有题目
（这一轮就是 SKILL.md 第 0 步第 1 条，通常已经问过；问过就直接从第 2 轮开始。）

| 问题 | 选项 |
|---|---|
| 你是哪个学术方向？ | MPA 公共管理（推荐）/ 其他社科 / 理工方向 |
| 题目现在是什么状态？ | 已定题 / 有大致范围 / 完全没想好 |

- 选「已定题」→ **跳过本文件**，回 SKILL.md 第 0 步第 5 条复核研究层次与论文类型。
- 选「理工方向」→ 编号改 `第一章/1.1/1.1.1`，候选卡的"论文类型"一栏改按理工惯例给（不再套 MPA 四类）。
- 选「有大致范围」→ 直接进第 2 轮，但第 2 轮③可以从用户已有的范围出发给选项，不用完全从零。

### 第 2 轮：攒素材（四问齐发）

> **核心逻辑：①② 定行业 → ③ 用行业锁领域 → ④ 用材料锁类型。四问缺一不可，顺序不可变。**

| 问题 | 选项要点 | 说明 |
|---|---|---|
| **① 你的工作岗位/行业大类？** | 体制内（机关/事业）/ 国企·国有平台 / 体制外（民企·外企·社会组织）/ 学生·应届 | 四选一，决定②的分支 |
| **② 行业细分？** | 由①动态生成（见下方分支表） | ①答"学生·应届"→ **跳过②**，直接进③ |

| **④ 你能拿到什么类型的材料？** | 能拿一手材料·能访谈 / 能发问卷（≥200份且本人发放）/ 只有公开资料 / 不确定 | 四选一，直接决定候选卡里的论文类型 |

**② 的动态分支表**（严格按①的答案生成②的选项）：

| ①的答案 | ②的选项 |
|---|---|

| 国企·国有平台 | 金融类（银行/证券/保险） / 能源通信基建类（电网/油气/电信/交通/市政） / 制造消费类（装备制造/消费品/商贸） / 其他跨类 |
| 体制外 | 民企·外企 / 社会组织·自由职业 |
| 学生·应届 | **跳过②**，③直接用"学生·应届"行的领域 |

**①答"其他跨类"时的③处理**：用户①选了国企但②答"其他跨类"，说明行业细分没法精确。此时③给"国企通用"选项：①数字治理·数据要素 ②产业发展·营商环境 ③国企改革与公共企业治理 ④应急管理·公共安全。

**①答了表外行业时的处理**（如自由职业者、创业者等未列入表 A 的）：②问"你的工作主要跟哪个领域打交道？"，③用领域候选库里最贴近的4个 + Other兜底。

**③选了 Other 自填领域时的处理**：用户自填的领域**直接采纳**，不要质疑"这个方向能不能写"。后面候选卡就围绕这个自填领域来设计——可行性和能不能写的问题在候选卡里用"风险"一栏体现，不在选题阶段否定用户。

## 二、候选卡格式（生成 3–5 个，逐条按这个结构写）

每个候选**必须**含以下七栏。缺「需要什么数据」或「风险」的候选等于没做可行性判断，不要交付。

```
### X. 简短题目：一句话点出研究什么

**问题意识**——为什么这事值得研究、现有研究缺什么、用户能补上什么。
用大白话写，别写成摘要腔。

- **你需要**：具体到能对照自查的程度（近1-2年台账清单 / 访谈8-12人 / 问卷200份）
- **类型**：案例分析型 / 调研分析型 / 政策分析型 / 问题研究型（按 SKILL.md 决策树判）
- **创新点**：一句话说清新在哪——理论应用新 / 方法新 / 视角新 / 对象新（见 SKILL.md「创新之处」六方面）
- **文献**：★★★★★ 最好 ~ ★★ 偏薄，并说明理由（是否热点、量表是否成熟、中文文献够不够）
- **风险**：这条最可能死在哪。要具体——"问卷发不出去就全盘作废"胜过"存在一定风险"
- **有先例吗**：有获奖论文/已发表的类似题目 → 说明出处；没有 → 坦诚说"暂未查到完全对口的"
```

写候选卡的几条硬规矩：

1. **按用户实际能拿到的材料设计**，不是凭空出题。用户说只有公开资料，就不要给需要内部台账的候选。
2. **文献可得性优先**（便于后续做综述）：量表成熟的实证题、有热点文献支撑的题优先给；文献偏薄的可以给但要标 ★★ 并说明。
3. **风险要写死在哪一点上**。风险集中在单点的（如"必须发够 200 份问卷"）必须点明，因为那一点不成立整条就废。
4. **创新点必须给**。用户后面写"创新之处"一节最头疼的就是找不到新意，候选卡阶段就帮他点明。
5. **可以引参考范文**：`references/论文类型详解.md` 里有历届全国 MPA 优秀毕业论文题目，同题材有获奖先例是很强的可行性证据。
6. **不堆到 5 个**。3 个扎实的胜过 5 个注水的；用户背景窄时给 3 个就够。
7. **呈现方式：用 AskUserQuestion 让用户直接点选**。每个候选卡缩成一行 option：label 写题目（如"候选1：开源软件供应链安全风险的多层治理"），description 写一句话亮点+风险+推荐等级（如"⭐首选｜国企金融背景贴合｜需访谈4-6人"）。用户直接点选，不用读完 markdown 表格再回复"选3"。**推荐的排第一个**。
8. **3个候选要拉开距离**：同一个领域给3个不同切入点（如政策分析 + 实证调研 + 案例深挖），不要三个都是"XX问题与对策研究"的变体。

### 换一批（用户说"都不太感兴趣" / "换一批" / "有没有别的"）

用户看完第一批候选卡不满意是**正常流程**，不要觉得没做好。处理规则：

- **立刻给第二批**，不要问"为什么不感兴趣"——用户说不清，追问反而烦。直接换方向生成新 3–5 个，和第一批**不要撞车**（同一个大话题换说法不算换）。
- **换的方向依据**：回看用户三轮答过的所有信息，换一条没试过的路径：
  - 第一批偏问卷实证 → 第二批偏政策分析/案例深挖/公开数据
  - 第一批都在同一领域 → 第二批换领域（如从"基层治理"换到"数字政府"）
  - 用户在⑥里提到的工作场景 → 从那个场景里挖一个新角度
  - 用户闲聊里带出来的关键词（"我们单位最近在做XX"）→ 值得拿来转方向
- **最多换两批**。三批还选不定，停下来用 `AskUserQuestion` 把前两批的卡片**混编成一份精简清单**（每条缩成一行核心信息 + 风险一行），让用户"从这份清单里点一个"，而不是继续出新候选。能走到选题这一步的用户通常信息充足但犹豫，帮他收敛比继续发散更有效。
- **换第二批时仍然要给推荐**，和第一批一样说清首选/次选/不建议，不要只列卡片不给判断。

## 三、推荐意见（候选卡之后必须给）

列完候选不要就丢给用户挑——**明确说哪个首选、哪个次选、哪个不建议，并给理由**。用户找你就是要这个判断。

- **首选**：说清为什么（数据成本低 / 文献厚 / 创新点天然成立 / 有获奖先例）
- **次选**：给出它更优的条件（"如果你确实能发到 200 份问卷"）
- **不建议**：说清卡点（"要同时访到街道和条线部门两边，而这恰好是论证的命门"）

创新点可以顺带点明落在六方面的哪一个（见 SKILL.md「创新之处」），省得用户后面硬找新意。

## 四、收束

用户选定后（选定 = 从候选卡里点了一个，**包括经过换一批后选定**），把以下四个问题**合成一次 AskUserQuestion 一次性问清**（不要分四轮）：

| 问题 | 选项要点 |
|---|---|
| 题目具体聚焦哪个层级？ | 具体哪个社区 / 街道 / 区县（题目里要不要"以某某为例"） |
| 论文类型确认 | 用 SKILL.md 决策树复核（候选卡里已判过一次，这里再确认） |
| 要不要帮拟问卷/访谈提纲？（仅调研分析型、案例分析型、或用户答过"能发问卷/能访谈"） | 问卷 + 访谈提纲都要 / 只要其中一项 / 先不用，我自己写 |
| 篇幅偏好 | 精简(≈4000) / 标准(≈6000) / 充实(≈8000) / Other 自定义 |

问卷/访谈这问的**时机很关键**：样本量与量表维度要写进「研究方法」一节，等正文写完再问就得回头改。用户说不用就不做，但提醒他附录这项还空着（模板要求含问卷/访谈者须附提纲）。**此处问过，起草时不再重复问。**

四个问题都答完后，齐了就进 SKILL.md 起草流程第 2 步（联网检索文献）。

## 五、题目太大时先拆，不要打磨细节

用户给的题目若是"我国基层治理现代化研究""数字政府建设研究""公共服务均等化研究"这类**能写成一本专著**的，**第一件事是直接告诉他这个题目开不了题**——不要先去问访谈几人、问卷发多少份。在一个必须拆的题目上打磨细节是白费功夫。

收窄用四把刀，按顺序试：

| 收窄方式 | 例 | 切完的效果 |
|---|---|---|
| **限层级** | 基层治理现代化 → 街道层面的…… | 研究对象从"全国"缩到"一个街道" |
| **限对象** | 公共服务 → 社区养老服务 | 研究问题从"全部公共服务"缩到"一个具体服务" |
| **限政策/机制** | 数字政府建设 → "接诉即办"考核机制 | 研究内容从"整个数字政府"缩到"一个机制" |
| **限时段** | ……的演进 → 2020—2025 年…… | 时间跨度从"全部历史"缩到"近5年" |

一般切两刀就够开题了（如"街道层面接诉即办考核机制研究——以某街道为例"）。**判断标准**：题目缩到用户能在一篇 6000–8000 字的报告里把问题说清楚、把对策写具体，就到位了。收窄后的题目再回第 2 轮走常规流程。

**反过来也有**：题目已经窄到"某社区某月某活动的效果"这种，不足以支撑一篇学位论文，要往上提一层——把具体事件当案例，研究问题提到机制/制度层面。

## 六、大纲自查（交给用户之前自己先过一遍）

大纲写完先别急着发，按这四问扫一遍，**发现问题当场改掉，不必回头再查一轮**：

1. **占位扫描**：还有"待补""TBD""（此处展开）"或空着的小节吗？填掉。
2. **前后一致**：各节之间有没有互相打架？典型的——研究方法写了问卷调查，样本部分却只说访谈；创新之处讲的是分析框架，框架一节却没搭；题目说"以某街道为例"，正文却在谈全市。
3. **范围复核**：这份大纲是一篇开题报告能覆盖的量，还是又长成了一本书？超了就回第五节收窄。
4. **歧义复核**：有没有哪句话能读出两种意思？有就选定一种、写明确——含糊的地方到起草时一定会卡住。

## 关于 `brainstorming` 技能

**不依赖它，它的核心已经移植进本技能了。** 具体对应关系：

| brainstorming 的做法 | 本技能对应位置 |
|---|---|
| 定题前不许动手（HARD-GATE） | SKILL.md 第 0 步开头的「硬闸」——题目大纲未确认不写正文、不生成 docx |
| "太简单不需要设计"是反模式 | 同上：**看起来简单的题目恰恰是没说出口的假设最多的地方** |
| 一次只问一个问题、优先给选项 | 本文第一节三轮提问脚本（每轮 2–3 问，全部带选项） |
| 给 2–3 个带取舍的方案 + 明确推荐 | 本文第二、三节：候选卡七栏 + 必须给首选/次选/不建议 |
| 项目过大先分解，别先问细节 | 本文第五节：题目太大先拆（四把刀） |
| YAGNI，砍掉不必要的 | SKILL.md 第 0 步「砍到只剩必要的」——MPA 开题最常见的病是**堆**理论/方法/案例地 |
| 分节呈现、每节确认 | SKILL.md 起草流程第 4 步：文献综述与研究方法两节各停一次 |
| spec 自查（占位/矛盾/范围/歧义） | 本文第六节：大纲自查四问 |

**没有移植的部分**及原因：探查 git commits、开浏览器画 mockup、把 design doc 写进 `docs/superpowers/specs/` 并 commit、最后转 `writing-plans`——这些是软件设计流程，对选论文题目全是无关动作，写 design doc 还会污染用户工作目录，而 `writing-plans` 未必装了、照走会撞空。

所以：**环境里有没有 `brainstorming` 都不影响本技能，不要去调用它。**
