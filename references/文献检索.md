# 文献检索工作流（联网检索真实文献）

> 目的：为开题报告的**文献综述**和**参考文献表**提供真实的、可核验的文献来源，而不依赖记忆或臆造文献。撰写"（三）文献综述"一章前，先按本流程检索并整理文献，再动笔。

## 何时需要
- 用户要求"搜索/查/找参考文献""帮我检索文献""文献综述怎么写"时。
- 进入开题报告起草流程、准备写文献综述章节前，一律先检索（哪怕用户没明说）。

## 可用工具（按优先级）
1. **开放学术 API 直连（首选、最可靠）**：WebSearch/WebFetch 可能被组织网络策略拦截，但**开放 API 通常仍可经 `curl` 直连**，且能拿到结构化元数据（卷期页、DOI、年份），不必臆造。核心是 **OpenAlex**(`https://api.openalex.org`)：
   - 检索文献：`curl -s "https://api.openalex.org/works?search=<关键词>&per-page=25&select=title,publication_year,doi,authorships,primary_location"`
   - 可加 `filter=publication_year:2019-` 筛近年、`&sort=publication_year:desc` 按新到旧排、`&filter=type:article` 限期刊。
   - 中文主题也可用英文关键词检索（当前网格化/条块/负担等学术概念均有对应 English 文献），或检索中文作者的英文论文。
   - 仅凭 title/year/DOI 不够时，再用 WebFetch 抓 `https://doi.org/<doi>` 或期刊页核实卷期页码。
   - 备选开放源见文末"开放元数据源"。
2. **Playwright 浏览器自动化（中文文献主力，需环境支持）**：Playwright 能像真人一样打开浏览器访问知网/百度学术，不受 WebFetch 域名白名单限制。**先检测环境是否可用**：
   ```bash
   python3 -c "from playwright.sync_api import sync_playwright; print('OK')" 2>/dev/null
   ```
   - **可用** → 中文文献检索优先走 Playwright：`browser_navigate` 打开 `https://kns.cnki.net/kns8s/search`，`browser_fill_form` 填关键词，`browser_snapshot` 读取搜索结果（标题/作者/期刊/年份/摘要），`browser_click` 翻页。一次搜索能拿到 20 条结构化结果，比 WebSearch 靠谱得多。
   - **不可用** → 跳过，走下面第 3 级 WebSearch/百度学术兜底。**不要因为缺 Playwright 就放弃中文文献检索**。
3. **WebSearch / WebFetch**：WebSearch 发现线索、WebFetch 核实元数据。若返回空或"cannot verify domain safe"，**不要认定网络全断**，先改用上面的开放 API 直连。Playwright 不可用时，这是中文文献的主力通道（配合百度学术兜底）。
4. **学术检索 MCP**（如系统内存在知网/Scopus/WoS 相关 server）优先使用；中文学术库（CNKI/万方）若可访问，一并补中文文献。

## 检索策略（先想"我到底要找什么"）
1. **解析研究主题 → 提取检索词**：主题拆成「对象 + 问题 + 理论/方法」几组关键词。例："社区减负"→ 检索词 `社区减负`、`基层治理 形式主义 负担`、`社区治理 赋权`。
2. **中外文各检索一轮**：
   - 中文：**若 Playwright 可用**，直接打开知网 `https://kns.cnki.net/kns8s/search` 搜索（拿标题/作者/期刊/年份/摘要）；**若不可用**，用 `site:cnki.net <关键词>` WebSearch + 百度学术兜底。文献多为 MP 类期刊/学位论文。
   - 外文：OpenAlex API 检索（首选）；`Google Scholar`（`site:scholar.google.com`）补充；SSCI/英文公共管理期刊（Public Administration Review、Journal of Public Administration Research and Theory、Governance 等），英文检索词同步翻译。
3. **政策与官方文件**：政府官网、政策文件（如 `site:gov.cn <关键词> 政策`）——政策分析型尤其需要，作为一手资料文献。
4. **权威来源优先**：CSSCI/北大核心期刊、研究生学位论文数据库、官方政策文件；避免无名博客/论坛。

## 搜索不到时：分级处理（自动重试 → 真缺才问）
**原则**：绝大多数"搜不到"是检索通道/检索词问题，代理先自行重试；只有**多种渠道、多组词都检索不到、且波及文献综述主体**这种影响开题方向的"真缺"，才停下来问用户。**学术诚信底线：宁可缺几条、标待核验，绝不臆造卷期页码。**

### 第一级：自动换通道/换词重试（不打断用户）
出现空结果或工具被拦截时，按顺序自动尝试，**不要认定"这篇题没文献"**：
0. **先按主题类型预判命中率，再决定要不要排着换通道**。**工程/产业类交叉主题（如"软件供应链安全""信创""能源数字化"）对开放学术 API（OpenAlex/Crossref/arXiv/Semantic Scholar）的全文检索命中率普遍很低**——这类文献多在 IEEE、行业会议、行业报告和中文知网，开放源收录差；而纯学术概念类主题（社区治理、形式主义、社会保障）命中率高。若是前者，`WebSearch` 空 + OpenAlex 一轮相关度差即可视为"通道与本主题不匹配"，**不必把每条通道都试一遍**，直接跳到下面的收手标准或第二级。
1. **换检索通道**：WebSearch 空 → 改 OpenAlex/Crossref(见"开放元数据源"，curl 直连)；WebFetch 被拦 → 用 DOI 直连。
2. **换检索词**：中文题→译英文再搜；"对象+问题+视角"组合词→降维为只按对象/只按问题搜；加同义/上位词（"社区减负"→"基层治理""形式主义"）。
3. **上溯一级主题 / 横向扩展**：搜上位概念、相邻议题文献充作"研究现状"。
4. **用间接文献打底**：经典理论文献 + 官方政策文件先立住文献综述骨架——运营主体政府文件、监管机构官方报告常自带权威出处，可作为"研究现状"的骨架，不依赖学术库。
5. **收手标准（重要，避免空耗轮次）**：已试 **3 个不同通道**（开放 API + WebSearch + 百度学术兜底）、**≥2 组检索词**仍无可靠命中，或命中全部明显与主题无关时，**停止换通道**。不要无限重试——工程交叉主题常是”检索不到”而非”题没文献”，此时转到第二级（问用户要本地文献目录/放宽主题/按现有少量文献继续）。判定”通道与本主题不匹配”的充分信号：多通道都空 或 多通道都返回明显风马牛不相及的结果。”空结果”和”结果无关”同属无效命中，都计入失败次数。

**WebFetch 拦截识别**：WebFetch 返回"Unable to verify if domain … is safe to fetch / cannot verify domain safe"时，是**组织网络策略或企业安全策略拦截了该域**（尤其中文学术库、部分 .gov/.org），不是这个网页真不存在。此类情况**不要对同一域反复重试**，也**不要逐域试**——换用能过的通道，或直接认作"该来源通道被阻"进入收手标准。

### 第二级：真缺时才问用户（AskUserQuestion）
在**已尝试多种通道、多组检索词仍空空如也、且缺到写不成文献综述**时，停下来问用户，让用户选方向（勿自作主张）：
- **读取本地文献目录**：让用户选择是否提供一个**本地文献文件夹路径**（里面可能有用户已收集的 PDF/参考论文等）。**须经用户明确授权并给出路径后才读取**（本地文件属敏感访问，不可自行猜测或遍历无关目录）；获得路径后，读取目录内 PDF/文档，提取题名/作者/年份等作真实文献并整理著录，核验不出的标"待核验"。**用户也可以选择不填/跳过**，继续走下面的选项——本地目录是可选补充，不是必需。
- **放宽主题**：把研究对象/视角放宽到有文献的层次再检索（代理重试）；
- **换个方向**：在不脱离用户兴趣的前提下改可检索的相近选题；
- **按现有少量文献继续**：接受"直接对口研究尚少"作为研究空白，用可得的间接文献先写，剩余标注"待核验"由用户在知网补全。

#### 本地文献目录的具体读取方式（获得路径后执行）
1. **授权边界**：只用用户明确给出的路径；不遍历无关目录、不看用户未授权的文件；处理后即停，不残留引用到无权文件。
2. **列目录找文件**：`ls -R "<路径>"` 或 `find "<路径>" -type f` 列出目录内文件（PDF/docx/caj 等），先看有哪些、哪些是文献。
3. **提取可读文本**：
   - **PDF**：`pdftotext -enc UTF-8 "<file>.pdf" -` 转纯文本（macOS 预装/`brew install poppler`）。
   - **Word**：`textutil -convert txt -stdout "<file>.docx"`（macOS 自带，.doc/.docx 均可）。
   - **CAJ（知网）**：难以直接转文本/提取，先标注「待用知网客户端打开核验」；用户可自行复制题名页信息。
4. **提取著录元数据**：从首页/题名页/文末参考文献取：作者（≤3 全列、>3 前 3 加", 等"）、题名、刊名/出版单位、年份、卷(期)、页码；缺项按 GB/T 7714「连同标点一并略去」或标「待核验」。
5. **整理进参考文献表**：按 `references/参考文献著录.md` 编 [1][2]… 并入正文综述引用。核验不出的项**不要臆造**，明确标「待核验」，提示用户在校园网/知网补全。
6. **如实回报**：告诉用户读到了哪些文件、整理出多少条、哪些待核验、剩余哪些文件没读成（如 caj）。
> 安全原则重申：本地目录读取**永远在用户先授权并给路径之后**才发生；用户可随时选择不提供路径走其他选项，绝不因此卡住流程。

### 第三级：元数据补不全的处理
- 用 DOI/开放 API 补；补不上则按 GB/T 7714 "缺项连同标点一并略去"；
- 或明确标注"待核验"，提示用户在校园网/知网补全卷期页码；**不编造**。

### 定稿前提示
无论哪一级，最终交付时如实向用户说明：哪些检索渠道受限、哪些条目元数据待核验（尤其中文 CSSCI 需校园网/知网补全），给出补齐清单。

## 筛选与去重
- 保留与主题**高度相关**的近 5 年文献为主，结合经典文献打底（学科奠基性研究不算"旧"）。
- 去重：剔除非学术来源、重复条目、过时新闻；每条须能补齐完整著录信息。

## 整理成 GB/T 7714 条目
- 按 `references/参考文献著录.md` 规范著录，确定类型码（[J] 期刊 / [M] 专著 / [D] 学位论文 / [R] 报告 / [N] 报纸 / [EB/OL] 电子文献等）。
- **核验完整元数据**：作者（≤3 全列、>3 前 3 加", 等"）、题名、刊名/出版社、年份、卷(期)、页码；缺页/缺项时用 WebFetch 核实，实在查不到记录的才允许省略，不要臆造卷期页码。
- 顺序编号 `[1][2]…`，与正文引用标注对应。

## 支撑文献综述写作
检索结果按**主题/观点/方法论流派分类**（非罗列），再：
1. 归纳国内外研究现状（每类几句话 + 引用标注）；
2. 指出已有研究的不足/空白（"述而有论"的关键）；
3. 由空白过渡到本研究要回答的问题。
> 近 5 年文献占比宜过半；正文文献综述引用的条目数量 ≥15 篇。

## 质量自检（每批检索后核）
- [ ] 文献真实、元数据完整、可在网上找到出处；
- [ ] 主题相关、覆盖面（理论/现状/方法）均衡；
- [ ] 近几年文献占比过半、有经典文献打底；
- [ ] 已去重、已分类、可支撑"述而有论"；
- [ ] 总条目 ≥15 篇（综述引用 ≥15）。

## 开放元数据源（WebSearch 被拦截时的备用检索通道，curl 直连）
- **OpenAlex**：`https://api.openalex.org/works?search=<q>&per-page=25` — 免费、无需密钥、覆盖面广（含大量中国主题英文文献），返回 DOI/年份/作者/期刊。优先用它核验英文文献元数据。
- **Crossref**：`https://api.crossref.org/works?query=<q>&rows=20` — 免费，按 DOI 体系返回完整著录（卷期页）。
- **Semantic Scholar**：`https://api.semanticscholar.org/graph/v1/paper/search?query=<q>` — 可能限流(429)，重试或换源。
- 中文期刊（CSSCI/CNKI）元数据：上述开放源覆盖有限，**请在可访问知网/万方/维普的正式环境（校园网）补全中文文献并核验卷期页码**；技能内不臆造中文卷期页码，缺项按规范"连同标点一并略去"或明确标注"待核验"。
- **百度学术（兜底，中文 MPA 主题专用）**：当 OpenAlex/Crossref 对中文 MPA 主题命中差、WebFetch 又被知网/万方拦截时，用 **WebSearch 搜百度学术**作为兜底：
  ```
  WebSearch: site:xueshu.baidu.com <中文关键词>
  ```
  百度学术能返回：标题、作者、期刊/学位来源、年份、被引次数、摘要片段。用它**发现线索**（知道有哪些中文文献存在），再用 WebFetch 抓百度学术详情页核验作者和年份。**百度学术的卷期页码不完全可靠**，有余力时用知网二次核实；来不及就标注"待核验"。这条渠道的价值在于：不触发域名拦截、中文覆盖好、能快速摸清"这个方向中文文献大概有多少、集中在哪些期刊"。
